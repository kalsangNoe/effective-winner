## Architecture

A three-column blog. Reading the columns left → right maps directly onto the file layout:

- **Column 1 — post list** lives in `src/app/blog/layout.tsx`. It's a shared layout (not per-page) so the sidebar keeps its scroll/state across navigation. Renders `PostList` (client component, `usePathname` for active highlight).
- **Columns 2 & 3 — article + outline** are both rendered by `src/app/blog/[slug]/page.tsx` (the layout's `children`). The article is column 2; `Outline` (client) is column 3.

The two sidebars (columns 1 and 3) are borderless and are deliberately kept visually in sync: both `<aside>`s carry the same `pt-8`, and `PostList`/`Outline` share the same `nav`/heading/list markup and spacing (`p-4` nav, `px-3 pb-2` heading, `gap-0.5` list, `px-3 py-1` links) so their content starts at the same vertical and horizontal position. Change one and change the other to match, or the columns drift out of alignment.

Posts are **markdown files in `content/posts/`** (one file per post; the filename minus `.md` is the slug). `src/lib/posts.ts` reads and parses them — `gray-matter` for the YAML frontmatter (`title`, `date`, `description`) and `marked` for the body. This all happens in Server Components at build time, so there is no database and no runtime parsing cost. `getPost(slug)` returns the rendered `html` plus the extracted `headings`; `getPosts()` returns just the frontmatter metadata (newest first) for the sidebar.

The link between column 2 and column 3 is `slugify()` in `src/lib/posts.ts`: when rendering the body, `renderMarkdown()` injects `id="slugify(headingText)"` onto each `<h2>/<h3>`, and `extractHeadings()` builds the outline with the same `slugify`, so `Outline` links to `#slugify(headingText)`. **Both sides must use the same `slugify`** or in-page jumping breaks. `Outline` adds smooth-scroll + IntersectionObserver scroll-spy on top, but plain anchor jumping works without JS because the ids and hrefs already match.

Routing: `/` → redirect to `/blog` → redirect to the newest post, i.e. `getPosts()[0]` (`src/app/page.tsx`, `src/app/blog/page.tsx`). There is no standalone blog index; readers always land on a post so all three columns are populated.

The post body is rendered with `dangerouslySetInnerHTML` from `marked`'s output — **posts are trusted, author-controlled content, not user input**, and there is no HTML sanitization step. Do not feed untrusted markdown through this path without adding one.

### Adding a post

Drop a new `.md` file into `content/posts/` with `title`, `date`, and `description` frontmatter. The filename becomes the slug, `##`/`###` headings flow into the outline, and the route is statically generated automatically (`generateStaticParams`). No other files need to change.

## Conventions

- `@/*` path alias maps to `src/*` (see `tsconfig.json`).
- Styling is **Tailwind v4** via `@import "tailwindcss"` in `src/app/globals.css` (no `tailwind.config.js`; theme tokens are declared inline with `@theme`). Dark mode uses `prefers-color-scheme`. Rendered markdown bodies are the exception: they're plain HTML from `marked`, so they're styled by the hand-written `.prose` rules in `globals.css` (zinc palette, light + dark) rather than Tailwind utility classes.
- Default to Server Components; add `"use client"` only when a component needs hooks/browser APIs (currently just `PostList` and `Outline`).
- `params` is a `Promise` in this Next.js version — `await` it. Use the global `PageProps<'/route'>` / `LayoutProps` helpers (generated by `next dev`/`next build`) for typing.

## Per-column typography

Each of the three columns has its own font, font-size, line-height, and letter-spacing, driven by CSS variables rather than hard-coded values. The three column roots carry marker classes — `.typo-list` (column 1 `<aside>`), `.typo-article` (column 2 `<main>`, plus `.typo-date`/`.typo-title`/`.typo-desc` on the header elements), `.typo-outline` (column 3 `<aside>`). In `globals.css`, rules under those classes read `--typo-<col>-{font,scale,leading,tracking}` (`<col>` = `list` | `article` | `outline`): `scale` and `leading` are **multipliers** applied via `calc()` to the documented base size / line-height, `font` is a full font-family, `tracking` a letter-spacing. Every rule falls back to the base value, so an unset variable renders the column exactly as the base design (heading tracking and code's mono font are intentionally more specific and stay put).

The **applied** values live in the `:root` block of `globals.css` (see TYPOGRAPHY.md for the current numbers). They were tuned with `TypographySettings` (`src/app/components/typography-settings.tsx`) — a client "Aa Typography" bottom-bar popover with per-column controls and a device-font picker (`queryLocalFonts`). It is **currently dormant** (not mounted); its `DEFAULTS` mirror the `:root` values. To bring the live editor back, render `<TypographySettings />` in `blog/layout.tsx`; keep its `DEFAULTS` and the `:root` variables in sync when you change either.
